# Test Helpers

This directory contains helper utilities for running and maintaining tests in the Axway CLI project.

## LOG_TEST_OUTPUT Environment Variable

The `LOG_TEST_OUTPUT` environment variable enables detailed logging of test command invocations and their outputs. When enabled, it captures all command executions performed by `runAxwaySync()` and saves them to JSON log files in `test/.test-output-logs/`.

### Usage

Run tests with logging enabled:

```bash
LOG_TEST_OUTPUT=1 npm test -- test/commands/config/test-config.js
```

**Important:** It's recommended to run limited tests with this flag to avoid generating excessive log files. Target specific test files or test suites rather than running the entire test suite.

### What Gets Logged

For each test, a JSON log file is created containing an array of command invocations. Each invocation includes:

* `args` - Command arguments passed to the CLI
* `opts` - Execution options (e.g., `color`, `shim`)
* `status` - Exit code of the command
* `stdout` - Standard output captured from the command
* `stderr` - Standard error captured from the command
* `template` - Path to the mustache template file (when `renderRegexFromFile()` is called)

### Log File Location

Log files are created in `test/.test-output-logs/` with the naming convention:

* `<suite-name>_-_<test-name>.log` when Mocha test context is available
* `<command>_<args>.log` as fallback

### How It Works

1. **Capturing Output**: When `LOG_TEST_OUTPUT` is set, `runAxwaySync()` in [index.js](index.js) captures stdout, stderr, and exit codes for each command execution.

2. **Test Context Tracking**: The helper builds test names from Mocha's suite hierarchy (`describe` blocks) and test titles (`it` blocks) to create meaningful log file names.

3. **Template Association**: When `renderRegexFromFile()` is called to load an expected output template for assertion, it updates the most recent invocation in the log file with the template path. This links the actual output with the template it should match.

4. **Multiple Invocations**: Since tests often run multiple commands, log files store an array of invocations. This allows a single test to log multiple command executions.

## generate-template-from-log.js

This script processes log files generated by `LOG_TEST_OUTPUT=1` and creates or updates mustache template files that can be used for test assertions.

### Purpose

When maintaining tests, you often need to update expected output templates to match new CLI output. This script automates the conversion of actual command output into properly formatted mustache templates with appropriate variable substitutions.

### Usage

After running tests with `LOG_TEST_OUTPUT=1`:

```bash
node test/helpers/generate-template-from-log.js test/.test-output-logs/<logfile>.log
```

The script will:

1. Read all command invocations from the log file
2. For invocations with a `template` path (set by `renderRegexFromFile()`), generate a mustache template
3. Write the template to the specified path
4. Report how many templates were generated

### Template Transformations

The script applies several transformations to convert raw output into reusable templates:

#### Color Support

When the command was run with `color: true`, ANSI color codes are converted to mustache color tags:

```
\x1B[32mSuccess\x1B[39m → {{#green}}Success{{/green}}
```

Supported color functions: `bold`, `blue`, `cyan`, `gray`, `green`, `magenta`, `red`, `yellow`, `underline`

#### Version Numbers

Version numbers are replaced with the `{{version}}` variable:

```
1.2.3 → {{version}}
2.0.0-beta.1 → {{version}}
```

#### Years

Four-digit years (202X) are replaced with `{{year}}`:

```
2026 → {{year}}
```

### Example Workflow

1. Run a specific test with logging:
   ```bash
   LOG_TEST_OUTPUT=1 npm test -- test/commands/config/test-config.js --grep help
   ```

2. Check the generated log file:
   ```bash
   cat test/.test-output-logs/config_-_should-output-the-help-screen-with-color.log
   ```

3. Generate templates from the log:
   ```bash
   node test/helpers/generate-template-from-log.js \
     test/.test-output-logs/config_-_should-output-the-help-screen-with-color.log
   ```

4. Review the generated/updated mustache template files to ensure they're correct

5. Commit the updated templates

### Skip vs. Generated

The script tracks two categories:

* **Generated**: Invocations that had a `template` path and were processed successfully
* **Skipped**: Invocations without a `template` path (commands that weren't validated with `renderRegexFromFile()`)

If all invocations are skipped, it means the test didn't use `renderRegexFromFile()` to validate output, so no templates can be generated.

## Best Practices

1. **Targeted Logging**: Run specific test files rather than the entire suite to avoid log file proliferation
2. **Review Templates**: Always review generated templates before committing to ensure variable substitutions are correct
3. **Template Name Conventions**: Command output templates that expect to be compared to stderr should have a `-stderr` suffix to their filenames. `generate-template-from-log.js` will generate from stderr when referencing those files
4. **Clean Up**: Consider cleaning `test/.test-output-logs/` periodically as it's not tracked in git
5. **Template Variables**: Familiarize yourself with the available mustache variables in [index.js](index.js) `defaultVars` object for creating templates manually
